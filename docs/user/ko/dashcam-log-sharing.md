# 분석용 대시캠 로그 전송

[English](../en/dashcam-log-sharing.md)

주행 중 이상 동작을 당근마스터 또는 지정된 지원 담당자에게 분석 의뢰할 때는 Carrot Web의 `로그 > 대시캠`에서 문제가 발생한 구간을 찾아 전송합니다. 대시캠 로그는 화면에 보이는 영상만이 아니라 차량 상태와 제어 판단을 함께 확인할 수 있는 분석 자료입니다.

> [!WARNING]
> Carrot Web 조작은 반드시 안전하게 주차한 뒤 하세요. 주행 중에는 화면을 찾거나 로그를 선택하지 말고, 발생 시각과 증상만 기억해 두세요.

## 자동 커뮤니티 공유와 수동 로그 전송 구분

`시스템 > 녹화·전원 > DK 외부 자동 로그·진단 공유`는 comma Athena와 외부 제3자 자동 전송의 상위 동의이고, `Carrot 커뮤니티 데이터 공유`는 Carrot 커뮤니티용 하위 동의입니다. 둘 다 기본값이 꺼져 있으며 두 설정을 모두 켜야 Carrot 커뮤니티 서버나 내장 Discord로 장치·네트워크 상태, 설정값, 자동 onroad/예외 tmux 진단과 지원 메타데이터가 파일별 재확인 없이 전송되고 인기 설정값 다운로드와 CWP 주소 등록이 허용됩니다. 어느 하나를 끄면 새 커뮤니티 요청과 자동 tmux 캡처·재시도를 멈추고 대기 중인 자동 예외 전송을 버립니다.

두 공유 설정을 꺼도 사용자가 `로그 > 대시캠`에서 구간을 고르고 명시적으로 시작하는 수동 전송 자체, 사용자가 직접 지정한 NAS·Discord 주소, 아래 KA4 자동 검증 로그 전송의 별도 동의는 자동으로 바뀌지 않습니다. 단, 기본 `adot.synology.me` DK 수신처는 보안을 위해 KA4 자동검증 전용이며 수동 대시캠·tmux 전송을 HTTP 403으로 차단합니다. 수동 전송에는 별도로 인증된 개인 수신처가 필요합니다. 수동 로그 전송이 끝난 뒤 내장 기본 Discord로 결과를 자동 알리는 단계도 차단되므로 완료 화면의 결과를 직접 전달해야 합니다. 특히 `CarrotValidationAutoUpload`가 켜져 있으면 고정된 개인 NAS 수신처로 향하는 KA4 full rlog 전송은 두 공유 설정이 꺼져 있어도 계속될 수 있습니다. 세 설정의 동의 값은 백업·프로필·QR에 포함되지 않으므로 새 설치나 다른 장치에서 자동으로 켜지지 않습니다.

## KA4 자동 검증 로그 전송(시험)

`시스템 > 녹화·전원 > KA4 자동 검증 로그 전송 (시험)`은 사용자가 매번 로그를 찾거나 전송하지 않아도 되도록 만든 제한적 수집 기능입니다. 기본값은 꺼짐이며, 안전하게 주차한 상태에서 한 번 켜는 동작이 최대 7일 캠페인과 그 기간의 주행 후 자동 전송 전체에 대한 명시적 동의입니다. 로그마다 다시 확인하지 않습니다. 차량 제어 동작이나 `PathOffset` 값은 바꾸지 않으며, `Ka4StockSccStandstillRearm`은 별도 사용자 설정이 아니라 자동 적용 상태를 기록하는 내부 메타데이터입니다.

자동 수집은 다음 차량 구성이 모두 확인될 때만 준비됩니다.

- 소유자의 허용 목록에 등록된 DK 장치만 해당하며, 원본 식별자는 브랜치에 공개하지 않음
- 4세대 기아 카니발 KA4(현재 차량 검증 대상은 2023년식)
- CAN FD HDA1(비-HDA2) 순정 레이더 SCC와 PCM 크루즈
- openpilot 비롱컨이며 카메라 SCC가 아닌 구성

주행 중에는 자동 적용 상태에서 컨트롤러가 시험용 RES 프레임 요청을 큐에 넣은 경우와, 자동 적용 상태인데도 요청이 없었던 정차를 구분해 실패 분석에 사용합니다. OFF 상태 ID(`standstill_off`, `standstill_off_physical_res`)는 복원 전용 호환 분류입니다. 이전 버전이 이미 만든 캡처는 계속 전송하지만, 새 캠페인은 두 ID를 생성하지도 필수로 요구하지도 않습니다. 물리 RES 입력은 새 legacy OFF 이벤트를 만드는 대신 보존된 rlog에 그대로 남습니다. 또한 레인모드의 `PathOffset=0`과 `PathOffset=10`(오른쪽 10 cm), `AdjustLaneOffset=0` 조건을 구분합니다. 순정 SCC가 켜지고 운전자 페달 개입이 없는 상태에서 가까운 선행차에 접근하면서 `0.7 m/s²` 이상 가속이 `0.5초` 이상 이어지는 현상도 자동 선별합니다. `carState.ka4StockSccKeepaliveRequestCount`는 컨트롤러가 outgoing CAN 목록에 추가한 프레임 요청 횟수와 자격 정차 상태만 기록합니다. Panda의 실제 송신이나 순정 SCC ECU의 수신·수락을 증명하지 않으므로, ON 이벤트는 “컨트롤러 요청 관찰”을 뜻할 뿐 “차량 동작 변화 확인”을 뜻하지 않습니다.

조건이 감지되면 해당 세그먼트와 끊김 없이 이어진 앞쪽 최대 2개를 전용 임시 보존 대상으로 표시합니다. 가까운 선행차에 접근하면서 가속한 조건은 직후 제동 반응을 함께 보기 위해 다음 세그먼트가 완성되면 최대 1개 포함하고, 전체는 여전히 3개로 제한합니다. 이 표시는 운전자가 만든 로그 북마크와 별도로 관리되므로 자동 전송이 끝나거나 동의를 철회해도 운전자 북마크는 지우지 않습니다. 실제 전송은 주행이 끝나고 장치가 정지한 오프로드 상태이며 Wi-Fi가 연결될 때만 시작합니다. 사용자가 파일을 선택하거나 전송 버튼을 누를 필요가 없습니다. 진행 중 동의를 끄거나 다시 주행을 시작하거나 Wi-Fi가 끊기거나 캠페인이 만료되면 전송을 취소합니다.

자동 전송은 각 이벤트 캡처에서 **full rlog만 최대 3개** 보냅니다. 신규 캠페인은 실제 생성 가능한 조건 5개를 각 최대 2회 수집해 **최대 10개 캡처/서로 다른 full rlog 30개**를 선택합니다. 구버전에서 이미 보존된 legacy 조건 2개의 복원 호환 레코드까지 포함하면 상태가 다룰 수 있는 상한은 **14개 캡처/42개 rlog**입니다. 이 수치는 선택 항목 수 상한이지 전송 횟수나 바이트 상한이 아닙니다. 동시에 로컬에서 대기하는 큐는 최대 5개 캡처/750 MiB이지만 클라이언트 누적 전송량 상한은 없습니다. 별도 `qcamera`, 운전자 카메라, tmux 자료와 Discord 알림은 보내지 않습니다. 다만 full rlog 자체에는 정확한 위치, 차량 CAN과 제어 상태, 장치 식별자, 브랜치·커밋·작업 트리 수정 여부, route 시작 시점의 Params와 약 1분 주기의 저해상도 도로 썸네일이 포함될 수 있습니다. 기아 계기판 화면이나 실제 경고 문구는 rlog에 촬영되지 않으므로 로그만으로 문구 자체를 입증할 수는 없습니다.

전송할 때 장치는 기존 등록 키로 이번 요청의 일회용 난수에만 유효한 전용 인증값을 서명합니다. 수신 서버는 비공개로 미리 등록한 공개키 지문과 대조해 서명을 자체 검증하므로 범용 comma API 인증 토큰을 받거나 공식 comma 장치 API에 접속하지 않습니다. 사용자가 토큰이나 암호를 입력할 필요는 없습니다. 자동 검증 목적지는 표준 HTTPS 443의 루트 주소 `https://adot.synology.me` 하나로 고정됩니다. 사용자 정보, 다른 포트, 하위 경로, 쿼리·fragment, 서브도메인·유사 도메인과 임의 HTTPS 주소는 거부되며 배포 환경 변수도 이 고정을 바꿀 수 없습니다. Carrot Web의 일반 전송 목적지로도 우회할 수 없습니다. 수신 서버는 HDA2 플래그가 없는 정확한 HDA1 KA4 메타데이터와 각 파일의 크기·SHA-256이 모두 일치할 때만 저장하고, 장치는 캡처 ID·장치 ID·전체 파일 목록과 최종 manifest 해시가 정확히 일치하는 완료 영수증을 받은 뒤에만 로컬 대기 항목을 끝낸 것으로 처리합니다. 서버가 이 인증 규약을 지원하지 않거나 인증 확인이 일시적으로 불가능하면 로그는 로컬에 보존한 채 자동으로 재시도합니다.

대기 큐는 재부팅 후에도 유지되며 전송 실패 시 약 30초, 2분, 10분, 1시간, 6시간 간격에 소폭의 시간 분산을 더해 재시도하고 이후에는 약 6시간 간격으로 최대 7일 동안 계속할 수 있습니다. 파일 PUT 실패는 즉시 재시도할 수 있고 인증 또는 완료 영수증 실패 시 같은 캡처 전체가 다시 전송될 수 있습니다. 조건별 최대 2회, 전체 동시 대기 캡처 최대 5개와 약 750 MiB로 제한하지만 이는 누적 네트워크 전송 한도가 아닙니다. 수신 서버에는 장치별 일일 1 GiB 한도가 있으므로 한도에 도달하면 로컬에 보존된 로그가 다음 날 자동 재시도될 수 있습니다. 설정 줄에는 정리된 상태, 대기 건수, 만료 시각과 최근 전송 시각만 표시하며 route, 수신 URL, 장치·캡처 ID나 원문 오류는 표시하지 않습니다. 필수 조건 3개(정차 컨트롤러 요청, `PathOffset=10` 레인 주행, 가까운 선행차에 접근하며 나타나는 순정 SCC 가속)가 모두 전송되거나 7일이 지나면 설정은 자동으로 꺼집니다. 요청 없는 정차와 `PathOffset=0` 레인 캡처는 선택 진단이며, legacy OFF ID 2개는 완료 조건에 포함되지 않습니다. 사용자가 직접 끄면 대기 항목을 버리고 이 기능이 설정한 보존 표시를 해제합니다. 이 동의 값은 설정 백업·복원이나 QR로 다른 장치 또는 새 설치에 전달되지 않으며, 저장된 캠페인 상태가 없으면 주차 상태에서 다시 껐다 켜 명시적으로 동의해야 합니다.

Carrot Web에는 일반 사용자 로그인이 없지만, 이 고위험 동의의 활성화 토큰은 현재 Wi-Fi 기본 게이트웨이인 테더링 제공 휴대폰의 TCP 연결 또는 장치 로컬 연결에만 발급되고 같은 peer에 묶인 1회용 토큰으로 소비됩니다. 같은 핫스팟에 붙은 다른 LAN 클라이언트에서는 이 설정을 켤 수 없습니다. 다른 Carrot Web 기능은 여전히 로컬 네트워크를 신뢰하므로 강력하고 고유한 암호를 건 개인용 WPA2/WPA3 테더링·핫스팟에서만 사용하고 공용 Wi-Fi에서는 열지 마세요. 휴대폰 테더링 자동 전송은 모바일 데이터를 사용하며, 연속 캡처와 재시도로 누적 사용량이 동시 로컬 대기 한도인 750 MiB를 넘을 수 있습니다. 설정을 꺼도 이미 서버에 전송된 자료는 자동 삭제되지 않으므로 삭제가 필요하면 서버 관리자에게 요청해야 합니다.

## 전송 전에 기록할 내용

가능하면 다음 정보를 먼저 메모합니다.

- 발생 날짜와 시각: 분 단위까지 정확할수록 좋습니다.
- 증상: 급감속, 출발하지 않음, 차선 이탈, 경고음 등 실제로 관찰한 현상
- 당시 상황: 도로 종류, 대략적인 속도, 앞차 유무, 커브·합류·정체·신호 상태
- 반복 여부와 운전자의 개입: 브레이크, 가속 페달, 핸들 또는 버튼을 조작했는지
- 차량, 현재 브랜치와 커밋: `도구 > Info`에서 확인할 수 있습니다.

“이상했어요”보다 “14:32경 우측 합류 차량이 들어올 때 약 80 km/h에서 갑자기 감속했고 브레이크로 해제함”처럼 작성하면 필요한 구간을 훨씬 빨리 찾을 수 있습니다.

## 가장 빠른 방법: 방금 발생한 증상 보내기

1. 안전한 곳에 주차하고 주행이 끝날 때까지 기다립니다.
2. 브라우저에서 `http://장치-IP:7000`에 접속합니다.
3. `로그 > 대시캠`을 엽니다.
4. 오른쪽 위 로그 메뉴에서 `최근 5개 로그 전송`을 선택합니다.
5. 표시된 파일 수와 전송 용량을 확인하고 전송을 승인합니다.
6. 완료 화면에서 성공 수가 전체 수와 같은지 확인한 뒤 `복사`를 누릅니다.
7. 복사한 결과와 증상 정보를 지정된 당근마스터 또는 지원 담당자에게 보냅니다.

최근 로그 전송은 화면의 정렬 순서와 관계없이 가장 최근에 완료된 구간을 기준으로 선택합니다. 일반적인 일회성 증상은 앞뒤 상황이 함께 들어가는 `최근 5개`가 권장됩니다.

| 선택 | 적합한 경우 |
|---|---|
| 최근 2개 | 발생 시각이 확실하고 전송량을 최소화해야 할 때 |
| 최근 5개 | 방금 발생한 일회성 증상, 일반적인 분석 요청 |
| 최근 10개 | 발생 구간이 불확실하거나 같은 증상이 여러 번 이어졌을 때 |

## 정확한 구간을 찾아 보내기

대시캠 로그는 주행별 카드와 약 1분 단위의 세그먼트로 표시됩니다.

1. 발생 날짜와 시각이 들어 있는 주행 카드를 펼칩니다.
2. 세그먼트에 표시된 시각을 보고 문제 구간을 찾습니다.
3. 세그먼트를 눌러 영상을 재생하거나 메뉴의 `Replay`로 주행 데이터와 함께 확인합니다.
4. 문제 구간의 체크박스를 선택합니다.
5. 가능하면 문제 구간 바로 전 1개와 바로 다음 1개도 함께 선택합니다. 분석에는 증상 전후의 상황이 중요합니다.
6. 여러 구간이면 `선택 전송`, 전체 선택 또는 범위 선택을 사용합니다. 범위 입력은 `1`, `1-3`, `1, 3-5`처럼 사용할 수 있습니다.
7. 전송 확인 창에서 선택된 파일 수, 전체 크기와 모바일 데이터 경고를 확인합니다.
8. 전송을 시작하고 완료될 때까지 장치의 네트워크 연결을 유지합니다. 필요하면 진행 화면에서 취소할 수 있습니다.

현재 녹화 중이거나 아직 마무리되지 않은 세그먼트는 전송할 수 없습니다. 방금 끝난 구간이 보이지 않으면 잠시 기다리세요. 로그 화면은 사용 중일 때 약 10초 간격으로 목록을 새로 확인합니다.

## 전송 결과 확인과 분석 요청

완료 화면의 `업로드됨/전체` 숫자가 같으면 선택한 파일이 모두 전송된 것입니다. 일부 항목에 `FAILED`가 표시되거나 성공 수가 부족하면 실패한 구간을 다시 전송합니다.

`복사` 버튼으로 만든 결과에는 장치·브랜치·커밋 정보와 전송된 구간 결과가 포함될 수 있습니다. 성공한 각 구간은 Synology 공개 보기 링크로 표시됩니다. 링크를 열면 해당 구간의 주행 영상과 공개 파일을 웹에서 보고 Cabana, PlotJuggler, JotPluggler 실행 명령을 복사할 수 있습니다. 같은 route에서 번호가 연속된 구간은 한 번에 여는 묶음 링크도 함께 표시됩니다.

업로드 작업이 끝나면 장치가 같은 결과 보고서를 설정된 Discord 웹후크로 직접 전송합니다. 사용자가 별도 웹후크를 지정하지 않고 내장 기본 Discord를 사용할 때는 `DkThirdPartyDataSharing=1`과 `CarrotCommunityDataSharing=1`이 모두 필요합니다. 어느 동의든 꺼져 있거나 Discord 알림이 실패해도 이미 완료된 로그 업로드는 취소되지 않으므로, 완료 화면의 `복사` 결과를 채널에 직접 올리면 됩니다.

공개 보기 링크에는 로그인이 필요하지 않습니다. 링크를 받은 사람은 누구나 접근할 수 있으며 다른 곳으로 다시 전달할 수도 있습니다. 링크를 올릴 Discord 채널과 선택한 구간을 확인한 뒤 아래 내용을 덧붙여 분석을 요청하세요.

```text
차량:
발생 날짜/시각:
증상:
당시 속도와 도로 상황:
앞차 또는 주변 차량 상황:
운전자 개입:
재현 횟수:
전송 결과: (Carrot Web에서 복사한 내용)
화면 녹화: 있음 / 없음
```

한 번에 하나의 전송 작업만 실행됩니다. 브라우저를 잠시 닫았다가 다시 열어도 장치에서 같은 작업이 계속 실행 중이면 진행 상태나 결과가 다시 표시될 수 있습니다. 브라우저에 저장된 작업 번호는 장치의 실제 작업 상태를 다시 확인한 뒤 사용하며, 이미 끝났거나 존재하지 않는 작업 번호만으로 새 전송을 막지 않습니다. 장치에서 30분 동안 아무 활동도 없는 전송 작업은 실패한 작업으로 정리되어 다음 전송을 막지 않습니다.

## 화면 녹화도 함께 보낼 때

Carrot Web의 화면 녹화는 HUD, 경고와 화면 변화처럼 사용자가 본 현상을 설명하는 데 유용합니다.

1. 주행 전에 `주행` 화면의 `Record`를 눌러 녹화를 시작합니다.
2. `REC` 표시를 확인합니다.
3. 안전하게 주차한 뒤 `Record`를 다시 눌러 종료합니다.
4. `로그 > 화면녹화`에서 재생해 증상이 담겼는지 확인하고, 담당자가 요청하면 다운로드해 별도로 전달합니다.

화면 녹화만으로는 차량 제어 원인을 확인하기 어려울 수 있습니다. 이상 동작 분석에는 같은 시각의 대시캠 로그를 우선 전송하세요.

## 문제가 생겼을 때

| 증상 | 확인할 내용 |
|---|---|
| 방금 주행한 구간이 없음 | 주행이 완전히 끝났는지 확인하고 잠시 기다린 뒤 목록을 다시 확인합니다. |
| 녹화 중이거나 미완료라는 오류 | 해당 세그먼트가 마무리될 때까지 기다린 뒤 다시 선택합니다. |
| 이미 전송 중이라는 메시지 | Carrot Web이 장치의 기존 작업 상태를 다시 확인하고 진행 화면을 복원합니다. 실제 작업이 실행 중이면 완료 또는 취소를 기다립니다. 30분 동안 활동이 없는 작업은 자동으로 정리됩니다. |
| 전송이 멈추거나 실패 | 장치의 인터넷 연결을 확인하고 실패한 구간만 다시 전송합니다. |
| 일부 파일만 성공 | 완료 결과에서 실패 항목을 확인하고 해당 세그먼트를 다시 보냅니다. |
| 필요한 로그가 사라짐 | `도구 > delete all logs` 실행 여부와 저장 공간 정리 여부를 확인합니다. 삭제된 로그는 Carrot Web에서 복구하거나 전송할 수 없습니다. |

세그먼트 메뉴의 `qcamera`, `rlog`, `qlog` 다운로드는 담당자가 특정 원본 파일을 요청할 때 사용합니다. 일반적인 분석 요청은 `로그 전송` 또는 `선택 전송`을 사용하면 됩니다.

## 개인정보와 공유 주의

전송 자료에는 주행 영상, 위치·차량 상태 로그, 장치 식별자, 차량명, 브랜치와 커밋 정보가 포함될 수 있습니다. 공개 보기 링크는 서버에 파일이 남아 있는 동안 누구나 열 수 있으므로 전송 전 선택한 시각과 구간을 다시 확인하세요. 운전자 얼굴이 포함될 수 있는 `dcamera` 파일은 공개 보기와 분석 API에서 제외됩니다.
